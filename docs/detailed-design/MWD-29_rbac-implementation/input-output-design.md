# 入出力設計 (Input/Output Design)

RBAC自体はAPIの入出力構造を大きく変更しませんが、エラーレスポンスに影響します。

## レスポンス仕様

### 正常系

権限がある場合、通常のエンドポイントのレスポンスが返却されます。

### 異常系

権限がない場合、以下のエラーレスポンスが返却されます。

#### 403 Forbidden

```json
{
  "statusCode": 403,
  "message": "Forbidden resource",
  "error": "Forbidden"
}
```

## ロール定義

システムで利用可能なロールは以下の通りです。

| ロール名 | 値 | 説明 |
| --- | --- | --- |
| サービス管理者 | `SERVICE_ADMIN` | システム全体の管理権限を持つ |
| サービスメンバー | `SERVICE_MEMBER` | 一般的な利用権限を持つ |

## データベース変更

`users` テーブル（またはコレクション）に `role` カラムを追加します。

| カラム名 | 型 | 必須 | デフォルト値 | 説明 |
| --- | --- | --- | --- | --- |
| role | string (enum) | Yes | `SERVICE_MEMBER` | ユーザーのロール |

### 移行戦略 (Migration Strategy)

既存のユーザーデータには `role` カラムが存在しません。システムアップデート時に以下の手順でデータを移行します。

1. **デフォルト値の適用**: 既存の全ユーザーに対し、`role` カラムに `SERVICE_MEMBER` を設定するマイグレーションスクリプトを実行する。
2. **管理者の昇格**: 特定のユーザー（メールアドレス等で識別）を `SERVICE_ADMIN` に手動またはスクリプトで更新する。

RBAC自体はAPIの入出力構造を大きく変更しませんが、エラーレスポンスに影響します。

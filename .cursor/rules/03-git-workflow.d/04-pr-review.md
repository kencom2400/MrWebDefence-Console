## 4. PR作成・レビュー

### PR対応時のコメント追加

```
╔════════════════════════════════════════════════════════════╗
║  🚨 CRITICAL RULE - MUST EXECUTE 🚨                       ║
║                                                            ║
║  PRへの対応（修正）を行った場合、必ずPRにコメントを追加    ║
║  ユーザーやレビュアーに修正内容を伝える                    ║
║  コメントなしでの修正は禁止                                ║
╚════════════════════════════════════════════════════════════╝
```

#### 🚨 AIアシスタントへの絶対遵守ルール

**以下の場合、必ずPRにコメントを追加：**

1. ✅ **レビュー指摘事項への対応完了時**
   - Gemini Code Assistやレビュアーからの指摘を修正した場合
   - 修正内容を明確に記載

2. ✅ **追加の修正を行った時**
   - PR作成後に追加で修正を行った場合
   - 変更内容を説明

3. ✅ **質問への回答時**
   - レビュアーからの質問に回答する場合
   - 説明や補足情報を提供

**重要: 修正をコミット・プッシュした後、必ずPRにコメントを追加すること。**

#### PRコメントのテンプレート

##### レビュー指摘事項への対応完了

```markdown
## [レビュアー名/ツール名]レビュー指摘事項への対応完了

以下の指摘事項を修正しました：

### ✅ 修正完了項目

1. **[優先度] 指摘事項1**
   - 修正内容の説明
   - 変更したファイル

2. **[優先度] 指摘事項2**
   - 修正内容の説明
   - 変更したファイル

### 📝 修正内容の詳細

- 変更ファイル一覧
- 主な変更点
- 追加で実施した改善（あれば）

すべての修正をコミット・プッシュ済みです。
```

##### 追加修正の報告

```markdown
## 追加修正の報告

PR作成後に以下の追加修正を行いました：

### 修正内容

- [修正内容1]
- [修正内容2]

### 変更ファイル

- `path/to/file1` - [変更内容]
- `path/to/file2` - [変更内容]

すべての修正をコミット・プッシュ済みです。
```

#### PRコメント追加の方法

##### GitHub CLIを使用（推奨）

```bash
# PR番号を指定してコメントを追加
gh pr comment <PR番号> --body "コメント内容"

# または、ファイルから読み込む
gh pr comment <PR番号> --body-file comment.md
```

##### コメント内容の作成

```typescript
// ✅ 正しい実行方法
const commentBody = `## Geminiレビュー指摘事項への対応完了

以下の指摘事項を修正しました：

### ✅ 修正完了項目

1. **セキュリティ改善（High Priority）**
   - flyway.confでDB_PASSWORDのデフォルト値を削除
   - 未設定の場合はエラーになるように変更

すべての修正をコミット・プッシュ済みです。`;

run_terminal_cmd({
  command: `gh pr comment ${prNumber} --body "${commentBody}"`,
  required_permissions: ['all'],
});
```

**注意**: コメント本文に特殊文字（`$`, `` ` ``, `"`など）が含まれる場合、エスケープが必要な場合があります。その場合は、一時ファイルに書き出して`--body-file`オプションを使用することを推奨します。

#### PRコメント追加のタイミング

1. ✅ **修正をコミット・プッシュした直後**
   - 修正が完了したら即座にコメントを追加
   - レビュアーが変更を確認しやすくする

2. ✅ **複数の修正をまとめて対応した場合**
   - すべての修正が完了してから、まとめてコメントを追加
   - 各修正項目を明確に記載

3. ✅ **質問への回答時**
   - レビュアーからの質問に回答する場合
   - 必要に応じて追加の説明を提供

#### PRコメントのベストプラクティス

1. **明確な構造**
   - 見出しを使用して構造化
   - 修正項目をリスト形式で記載
   - 優先度や重要度を明示

2. **具体的な説明**
   - 何を修正したかを明確に記載
   - 変更したファイルを明示
   - 修正の理由を簡潔に説明

3. **完了の明示**
   - 「すべての修正をコミット・プッシュ済みです」と明記
   - レビュアーが確認しやすくする

4. **関連情報の提供**
   - 必要に応じて、関連するコミットハッシュを記載
   - 追加のドキュメントや参考情報へのリンクを提供

#### 避けるべきこと

1. ❌ **コメントなしでの修正**
   - 修正を行ったがコメントを追加しない
   - レビュアーが変更を把握できない

2. ❌ **曖昧な説明**
   - 「修正しました」だけのコメント
   - 何を修正したかが不明確

3. ❌ **修正内容の省略**
   - 重要な修正内容を記載しない
   - レビュアーが確認しにくい

## PR作成フロー

### 1. ブランチの準備

```bash
# 最新のmainブランチを取得
git checkout main
git pull origin main

# 新しいブランチを作成
git checkout -b feature/issue-<番号>-<説明>
```

### 2. 作業とコミット

```bash
# 作業を進める
# ...

# 定期的にコミット
git add .
git commit -m "適切なコミットメッセージ"

# リモートにプッシュ
git push origin feature/issue-<番号>-<説明>
```

### 3. PR作成

```bash
# GitHub CLIを使用
gh pr create \
  --title "<type>(<scope>): <subject>" \
  --body "$(cat .github/PULL_REQUEST_TEMPLATE.md)" \
  --base main
```

### 4. レビュー対応

```bash
# レビュー指摘事項を修正
# ...

# 修正をコミット・プッシュ
git add .
git commit -m "fix: レビュー指摘事項の修正"
git push origin feature/issue-<番号>-<説明>

# PRにコメントを追加（必須）
gh pr comment <PR番号> --body "## レビュー指摘事項への対応完了

以下の指摘事項を修正しました：

### ✅ 修正完了項目

1. **[優先度] 指摘事項1**
   - 修正内容

すべての修正をコミット・プッシュ済みです。"
```

### 5. マージ

- レビュアーの承認後、GitHub UIでマージ
- ローカルでmainブランチを更新

```bash
git checkout main
git pull origin main
```

## PR説明文の作成

### 必須項目

1. **概要**: 何を実装/修正したか簡潔に説明
2. **関連Issue**: `Closes #XXX`, `Related to #YYY` で明記
3. **変更内容**: カテゴリ別に変更内容を列挙
4. **実装状況**: チェックリストで進捗を明示
5. **テスト結果**: ローカルでの実行結果を記載
6. **変更ファイル**: 新規作成と更新ファイルを分けて記載
7. **レビュー観点**: 重点確認項目と注意点を明記

詳細は `.cursor/rules/templates/pr-description.md` を参照してください。
